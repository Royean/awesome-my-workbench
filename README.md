# 知衡 · 个人健康工作台

一个参考 TREK 结构化管理与助手交互的本地单用户健康后台，整合就医、锻炼、饮食、监测、计划和资料。

## 运行

需要 Node.js 24 或更新版本，无需安装依赖。

```sh
npm start
```

也可双击 `start.command` 启动。在此电脑打开 http://localhost:3100 。可通过 `PORT` 更换端口。当前电脑可直接使用：

```sh
/opt/homebrew/opt/node@24/bin/node server.mjs
```

## 已实现

- 健康总览：近期数值、分类趋势、今日计划、跨模块时间线、快捷记录。
- 就医：机构、科室、日期、状态、就诊记录与关联附件。
- 锻炼：运动类型、时长、日期、感受与累计时长。
- 饮食：餐次、时间、餐食与备注。
- 监测：体重、血压（双值）、睡眠、血糖、心率；按7/14/30天查看同类同单位趋势。
- 计划：分类、日期、时间、完成与取消完成。
- 资料：PDF、图片、TXT上传与下载，单文件10MB，关联就医；未实现OCR。
- 所有记录可编辑、搜索和按日期筛选；删除确认后可在12秒内撤销。
- 示例与个人空间分离，设置与数据持久化；JSON导出包括记录和文件元数据，不包括附件字节。
- 健康助手入口与本地统计摘要。**未连接AI模型，不提供模拟AI答复；无远端MCP服务。**

## 数据位置与边界

SQLite位于 `data/health.sqlite`，原始附件位于 `data/uploads/`。不自动读取既有私人健康仓库或Drive，也不覆盖它们。个人空间初始为空，示例数值均为虚构。备份时停止服务并复制整个 `data/` 目录（若热备份则需使用SQLite备份机制）。删除资料只移除界面记录，原始附件保留在本机，以支持撤销；此版本不作自动文件清理。

当前仅绑定 `127.0.0.1`，适合个人本机试用，无账户权限、设备同步、消息通知或远程访问配置。计划是应用内待办，不会发送系统通知。记录仅用于整理与回顾，不做自动诊断、处方或医疗阈值判定。

## v0.2 就医流程

从「就医管理」打开一次就诊，可在同一详情中管理：

- **就诊记录**：医生、就诊原因、医生记录/结论原文、医嘱与旧备注。
- **就诊报告**：就诊记录、检验/影像、处方、出院记录等，手录原文与来源，待出报告/待补充/待核对/归档；同表单上传原件或关联已有附件，支持PDF、图片、TXT预览及下载。不会OCR或生成诊断。
- **用药方案与服用记录**：按原处方填写用量、途径、频次，指定时段或按需记录。逐次填写实际服用时间或跳过原因，历史可更正/删除撤销；停用后不再生成待服事项，历史仍保留。已有服用历史的方案不能直接删除，应停用或先处理历史。
- **复查与待办**：在详情直接建立关联任务，在全局健康计划可返回本次就诊。

全局就医管理也提供「用药管理」「就诊报告」入口，便于跨就诊查找；首页显示进行中方案的今日服用时段。这里只提供应用内待办与手工记录，没有系统通知或自动开药。

v0.2独立验收记录：`docs/MEDICAL_ACCEPTANCE.md`。原v0.1验收保留为历史证据。

## v0.3 快捷记录

首页上方四个入口和各模块“添加记录”进入精简表单，已有记录仍用完整表单编辑。

- **记一餐**：写一句话、选照片或录原始语音即可保存。日期、时间和餐次默认带入；备注可留空。照片/原始音频可在饮食列表查看或回放。没有自动识别、热量估算或语音转写；原件原样保留。麦克风需浏览器授权，录音最长90秒。餐食文字最多5000字，附件最多4个、合计10MB，支持JPG/PNG/WEBP和WEBM/M4A/OGG/MP3。
- **记运动**：点项目、选时长快捷值或复用最近一次的项目与时长，名称自动生成。
- **记数值**：选体重、血压等，直接输入；名称与单位自动生成，不预填上次结果。
- **传报告**：先上传原件，进入资料档案“待整理”，无需现场填医院或关联就诊。后续“整理为就诊报告”补充来源；已整理的原件可直接查看对应报告。

餐食原话和媒体通过一个事务保存，校验失败不会残留半条记录；单独上传报告原件即代表原件已保存，后续整理可以另行完成。文件导出的JSON仅含元数据，完整备份仍需复制整个data目录。

v0.3独立验收见 `docs/QUICK_ACCEPTANCE.md`。

## v0.5 饮食与锻炼的日常功能

- 锻炼支持常用收藏、复制训练、距离、感受及动作/组数/次数/重量明细；新增记录默认今天，从每日回顾补记沿用选定日期。
- 饮食支持常吃收藏、份量、照片/录音追加和移除，移除旧照片后可选择新图替换。编辑保留原ID，附件事务更新；解除附件关系不销毁原件。
- 饮水记录支持快捷杯量、自定义ml、补记、修改、删除与撤销。
- 每日回顾统一按日期汇总餐食、运动时长和饮水，并可回看明细和补记。
- 收藏只复制文字和训练模板，不复制旧日期、时间或餐食照片。

私有部署另有同级 `health-workbench-online` 源码，使用Sites登录、D1与R2，按用户和空间隔离。线上个人空间初始为空，不会自动迁移本机真实记录。详见 `docs/DAILY_ACCEPTANCE.md`。

## GitHub代码分支

- `main`：Node.js + SQLite 的本地及腾讯云独立托管版本，包含手机版多工作台、账号系统及部署配置。
- `cloud`：Vinext + D1 + R2 的线上部署版，包含登录保护和云端数据库迁移。

两分支是同一应用的不同运行版本。若需要同步开发，请分别检出为相邻目录 `health-workbench` 与 `health-workbench-online`；云端的同步脚本会从相邻本地版读取业务验证与页面源码。仓库不含真实数据库、用户附件或访问凭据。

## 独立账号与腾讯云

腾讯云访问：[Awesome My Workbench](https://vivid-dream.online/)；运行版本与验证证据见 [腾讯云发布记录](docs/TENCENT_DEPLOYMENT.md)。

`main` 的 v0.7 提供独立登录、管理员邀请、账号禁用、改密及会话管理。用户、工作台和示例/个人空间分别隔离；管理员不会自动取得其他用户的健康资料。使用 Node 24 LTS，`npm test` 串行运行隔离回归。

生产配置参照 `.env.example`，设计和验收条件见 [账号与部署设计](docs/ACCOUNTS_AND_TENCENT.md)。发布目录中的 `deploy/install-release.sh RELEASE_ID DOMAIN` 安装独立 systemd 服务及 Nginx 虚拟主机；需要事先安装独立 Node24 runtime、配置域名及有效证书。脚本只在环境文件不存在时创建配置；已有配置保持原值。

首位管理员由服务器 CLI 的 `create-admin-invitation --email EMAIL --name NAME` 建立，一次性令牌只在初始化时输出，24 小时有效，使用者自行设置密码；没有默认密码或公开注册。邀请码应私下交付，不写入 Git、Issue 或日志。会员邀请由登录后的“我的 → 账号与安全 → 成员管理”执行。当前不发送邮件、不自动迁移 Sites 或本机已有资料。

注意：`cloud` 分支仍是原 Sites 平台版本，未移植独立账号服务。不要把 `main` 的账号页面直接同步到 Sites 并据此声称具有同样的账户管理功能。
