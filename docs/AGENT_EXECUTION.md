# Agent 任务执行

开发工作台的「Agent 任务」支持手动分配，以及由产品经理 Agent 生成计划并按依赖分配。AI Teams 展示同一份设备、任务和运行记录。角色目录中的成员会自动进入团队，已有同角色成员沿用原记录。

## 接入 Mac

连接程序需要本机 Node.js 24、Git 和已登录的 Codex CLI。打开 Workbench Agent Bridge，在「AI Teams → 设备」生成一次性配对码并完成配对。从 Mac 菜单添加允许执行的 Git 项目目录，设备会发布项目名称、Codex 就绪状态及 Skills/MCP 核验结果。

设备凭据保存在 macOS 钥匙串。项目绝对路径和 Codex 登录保留在 Mac，工作台只接收项目 ID、名称和任务事件。私人角色正文由服务器外部目录提供，在委派时发送给对应设备，源码仓库仅含通用角色定义。

运行 `npm run build:agent-bridge` 构建本机应用。产物位于 `output/agent-bridge/`，包含菜单栏应用、ZIP 和校验文件。当前构建使用本机架构及临时签名，首次从浏览器下载时需通过 macOS 的打开确认。

## 委派任务

先为 Agent 选择默认设备、Codex harness 和项目，也可以在创建任务时调整。选中的设备须在线、Codex 已登录，任务要求的 Skills 和 MCP 须通过核验。

手动模式运行选定 Agent。自动模式调用产品经理 Agent，使用其实际生成的计划建立子任务及依赖。首版同一自动工作流使用所选设备和项目，各角色共享该工作流的隔离 Git worktree。前置子任务执行成功并回传结果后，后继任务才可领取，交接结果随任务传入。

每次重试生成新的运行记录。界面显示真实 Codex 会话标识、阶段、审批、输入请求、同步时间及结果。运行成功后进入「待验收」。可在执行 Mac 上打开任务工作目录，检查实际文件及差异。

## 连接与恢复

连接程序在任务执行时保持同步。Codex 请求操作批准或补充输入时，工作台显示对应请求，回答会送回原会话。执行 API 使用完整登录会话，资料类个人访问令牌不能配对设备、派发任务或批准本机操作。

开始模型执行前，连接程序先持久保存运行身份并等待服务器确认。事件按序重传，已确认事件可重复提交。断线后保留最后记录；无法确认旧进程已经停止的运行显示「状态待确认」，不会自动重新启动。设备离线、会话结束、代码交付和任务验收分别记录。

协议与本地配置详见 [connector/README.md](../connector/README.md)。Codex 接口依据 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。
