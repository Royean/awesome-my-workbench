# AI 可编辑健康首页

关联 Issue #63。第一版基于7680b5f，仅健康dashboard，其他工作台与业务模块保持现有实现。

实际分工：协调/前端实现 `/root`；布局服务、迁移、MCP与后端测试 `/root/layout_backend`；UI设计检查/独立代码评审 `/root/layout_review`；独立验收 `/root/layout_acceptance`。按私人角色库的软件开发协作规范执行，独立报告不是GitHub正式审批。

## 使用方式

健康首页标题旁或「我的→首页布局」打开编辑器。选择手机或电脑，调整卡片顺序、显隐和支持的大小；趋势可设置项目及7/14/30天范围，待办可选择1–8项。默认仍显示最近5项未完成待办。主题色对整个健康工作台共用，个人与示例空间共用外观。

预览不会改变当前配置、主题或任何业务记录。相同尺寸直接显示实际卡片，跨尺寸使用同源私有iframe呈现390px手机或1440px电脑。预览可继续编辑、应用、退出；子框架只查看布局，保留趋势查看但不允许提交业务或布局修改。预览链接1小时有效，必须登录所属账号。未登录打开会保留目标，登录后显示对应预览。

应用后持久化；刷新、换设备或切数据空间仍保留。恢复当前设备默认只改该设备排列；历史恢复包含当时双端布局和主题色，并创建新版本。保留初始版本和最近30次版本。

AI连接刷新知衡工具列表后，可接受“把手机饮水放最前，隐藏运动，电脑保持原样”等自然语言指令，使用 `list_layout_widgets` / `get_layout` / `preview_layout` / `update_layout` / `restore_layout`。自然语言理解由连接知衡的AI承担，应用中没有新增模型服务或模拟聊天机器人。

## 配置与实现

`public/layout-config.js` 是组件目录与白名单配置的共享合同；9个组件来自现有真实卡片。只有设备mode变为custom时才进入响应式画布，默认继续使用原来的Studio组合。不能注入HTML、CSS、SQL、外部数据源或任意执行动作。

`public/layout-editor.js` 管理草稿、真实尺寸预览、保存/冲突/恢复、上下文取消和布局读取；`public/layout.css` 只补编辑画布与控件。配置按账号+工作台+页面保存，独立于健康记录、上传文件和personal/demo数据空间。

API/MCP共用 `lib/layouts.mjs`，布局、版本与主题同事务。每次变更必须携带读取时的revision。冲突保留草稿，“读取最新并保留我的调整”将用户实际改动合并进新草稿供检查，不自动重试覆盖。保存中禁止正常关闭；取消预览后晚到响应不重开界面，旧异步finally不能改变新操作的状态。所有API读取/写入都校验账号归属，MCP复用现有令牌授权。

配置刷新在健康首页可见且没有抽屉/预览时进行，每30秒检查布局版本；重新聚焦也检查。外部AI变更会清理个人/示例缓存并重新读取。断网保留当前显示，不自动重复提交写入。

迁移006仅新增当前布局、版本、预览三表；旧库首次读取默认不创建用户偏好。CSP默认禁止嵌入，仅当前账号合法有效的根预览GET允许同源框架；其他页面、匿名/跨账号/过期、非根路径仍禁止。

## 验收条件

- 默认布局与现有数据行为保留；双端独立排序、大小、显隐及展示选项生效。
- 编辑/预览/应用/取消与dirty关闭保护正确；恢复/默认不会改动健康记录。
- 私有预览、账号隔离、有效期、并发revision、重启、升级与事务失败完整验证。
- 360/390/430/820/1440布局及真实交互验证；其余四台与沉浸阅读回归。
- 独立验收、代码复核、目标提交CI与部署实际文件核验后关闭Issue。
