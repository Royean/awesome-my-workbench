# 登录与切换性能独立验收

测试设计及初段执行：测试验收工程师 Agent `/root/performance_qa`，独立于实现作者。最终集成后的执行与结果整理：`/root`（作者复跑），不冒充独立执行。依据私人角色规范 `agents/roles/test-acceptance-engineer/ROLE.md` 和软件开发协作工作流。验收范围是减少重复启动请求、静态资源缓存、切台反馈和网络失败恢复；不等同于安卓设备验收或生产部署验证。

## 环境与隔离

基线提交 `fb3d3b23f943e8d4aea6fe9eed46f62878320574`；在该基线上验收本次集成后的工作区代码，最终提交由协调负责人补充。Node 24，本机 Chrome headless，360×844 / 390×844 移动视口。真实本地 Node 后端启用 `AUTH_REQUIRED=1`，动态独立端口，`HEALTH_DATA_DIR` 指向执行后自动删除的系统临时目录。全部账号、备忘和附件均虚构，不访问 3100 及真实数据，不连接手机、不安装 SDK 或新依赖。邀请 token 与随机密码仅在进程内使用，不进入日志或报告。

## 计划与用例

- AC-P01：实际返回的 index 仅引用 fingerprint JS/CSS，浏览器执行真实 bundle，能显示登录与工作台；登录和邀请激活成功各一次 POST + 一次 state，无 document navigation，无再次 me。
- AC-P02：普通底部导航不发请求。warm reload JS/CSS `transferSize=0` 且有解码内容，资源来自浏览器缓存。
- AC-P03：健康/金融与个人/示例空间不串资料；持有刷新请求时，30秒内同用户同空间的工作台缓存先显示。保存后可立即看到最新记录。
- AC-P04：API、账号与真实上传文件均 `Cache-Control: no-store`；公共不可变资源缓存与内容升级 hash 变更由 `tests/assets-cache.test.mjs` 补充验证。
- AC-P05：读超时显示重新连接，写超时恢复登录按钮；失败写不自动重试，用户手动重试成功。浏览器注入仅将 15/30/60 秒的定时器加速至120ms，后端真实，停滞网络由路由模拟；不将此模拟当成实测移动网络耗时。
- AC-P06：401 后工作台内容清除，换成其他用户登录不会恢复上一用户私有缓存。浏览器没有未捕获脚本错误。

## 可复现命令

无需下载依赖，复用本地已有 Playwright（路径可按环境替换）：

```sh
PLAYWRIGHT_MODULE=file:///path/to/playwright/index.mjs node tests/performance-acceptance.mjs
npm test
```

浏览器测试先核对服务实际返回的 bundle；实现作者需先运行构建，避免旧 fingerprint 资源造成结果偏差。全量测试使用项目既有 `--test-concurrency=1` 串行执行，避免测试固定端口碰撞。

## 执行结果

最终集成后由 `/root` 执行：Node 串行全套 **50/50通过**，真实 Node/SQLite + Chrome 移动视口 **15组通过**。独立QA此前实际运行了49项初步回归及前段浏览器检查，并发现hash导航重复请求favicon；最终修复favicon和空间切换加载状态后由整合作者复跑，不能将最终执行冒充独立Agent执行。

真实浏览器断言通过：指纹bundle实际执行；登录及邀请均一次POST+一次state、无document重载和重复me；底部切页零请求；warm reload两个资源transferSize=0；持有后台state请求时先显示同用户已加载内容；健康/金融、示例/个人隔离；写失败代次变化后重新GET并退出loading；上传文件与API不缓存；加速超时后按钮恢复、写中断提示结果未知且不自动重试；退出换账号及401均清旧内容；无未捕获脚本错误。

执行中发现并修复：切换示例/个人空间等待请求时仍短暂保留原空间DOM，现在立即展示明确的切换状态。测试脚本的超时加速仅用于故障注入，恢复正常计时后再验证实际scrypt登录成功；不把120ms测试截止时间当作生产配置。
