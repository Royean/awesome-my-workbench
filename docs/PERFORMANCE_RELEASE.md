# v0.7.1 加载优化发布

2026-10-31（Asia/Shanghai），部署及最终验证执行者 `/root`。运行源码提交 `f7bc8c8`，腾讯云发布目录 `releases/f7bc8c8`。部署包SHA256：`f8ba8bc3c783e1618932dff4e014e9ed9d87e2b0ae0cd1e6ba18ed9b07a45951`，上传后已核验。部署前在线SQLite及附件备份已成功生成，既有数据库和会话未迁移或清空。

## 行为变化

- 登录与邀请激活成功后直接加载工作台数据；不再重载document或重复读取me。
- 合并为一个指纹JS、一个指纹CSS，内容匹配哈希才允许一年immutable公共缓存。源改动生成新URL，HTML保持no-store，旧资产保留兼容已打开页面。
- favicon内联，消除hash导航的重复图标请求。普通底部切页无网络请求。
- 最近30秒、最多8个用户/工作台/数据空间条目的缓存仅存在本次页面内存；切回先显示最近内容并后台刷新。写入开始和结束/失败均失效缓存；失效、退出及用户切换清缓存与旧视图。
- 读请求15秒、普通写30秒、上传60秒超时。写入超时、中断或无效响应提示先刷新确认，避免重复提交；不自动重试写入。
- 私人API、附件、账号与用户数据仍no-store，不写入浏览器持久缓存或Service Worker业务缓存。

## 证据与边界

50/50自动回归、15组真实后端与Chrome移动视口检查通过。独立角色分工、已发现缺陷和实际执行人分别见[验收报告](PERFORMANCE_ACCEPTANCE.md)与[评审报告](PERFORMANCE_REVIEW.md)；最终作者复跑不冒充独立Agent执行。

公网验证：healthz正常；首页和真实新指纹资产可访问，公共资产返回`public,max-age=31536000,immutable`；auth/me GET返回enabled=true/user=null，匿名state为401；服务、Nginx和既有Inflow保持active；APK下载地址继续可用。生产部署无需重新构建或安装Android APK。

公网Chrome390px真实测量一组：冷启动登录页显示3753ms，随后重载1571ms；warm阶段JS/CSS的transferSize均为0，有解码内容，无未捕获脚本错误。此前另一组旧版本测量为1677/905ms，公网链路和出站节点波动明显、未做严格同条件控制，因此**不能据此声称整体耗时已经变短或手机慢已解决**。测量证明的是重复程序下载已消除；首次连接与API网络等待仍在。

此版本仍是原WebView APK所加载的页面，未完成原生安卓界面改造。未在用户实体手机验证实际延迟，用户需在APK右上角菜单「重新加载」，或彻底退出后重新打开，使用新版本再确认登录和操作表现。
