## 结果与缺陷

冻结版本最终API回归22/22通过（新增6组、旧基础9组、旧就诊7组），均在3105依次运行，各组使用新的系统临时目录。命令：

```sh
/opt/homebrew/opt/node@24/bin/node --test tests/quick-capture.test.mjs
TEST_PORT=3105 /opt/homebrew/opt/node@24/bin/node --test tests/acceptance.test.mjs
MEDICAL_TEST_PORT=3105 /opt/homebrew/opt/node@24/bin/node --test tests/medical.test.mjs
```

新增6组覆盖：5000字完整原话与5001字拒绝、默认日期/餐次及服务重启；照片/原始音频字节一致和下载MIME；跨空间引用/读取/编辑拒绝；空输入、类型、数量、10MB、非法日期时间失败且数据库与磁盘无残留；失败后重试；原话/附件ID编辑及撤销保护；孤立附件的历史记录可编辑；无就诊报告先上传→后续关联→原件字节及重启；运动时长边界和监测固定单位。

API样本为虚构图片/音频字节，证明存储保真及权限边界，不单独证明媒体解码与录音功能。

## 真实浏览器验收

使用独立3105临时实例、Chromium、空个人空间，未访问3100。以下均为真实页面交互，不以API代替UI：

- QUICK-AC01通过：1440×1000桌面四入口可操作，位于首页上方；390×844手机首页与餐食表单文档宽度均390，无横向溢出。
- QUICK-AC02通过：空餐保存给出明确错误；一句话含换行、脚本文字及前后空白保存原话完整，脚本文字正常显示。仅照片可保存，上传时blob预览及列表原件预览实际解码为1px测试图片。最新11点默认午餐，日期/时间已填。
- QUICK-AC03通过：选择骑行与30分钟即可保存；点最近运动填入相同类型/时长后保存，生成两条独立记录，原记录未改动。
- QUICK-AC04通过：血压120/125被拒绝，120与125草稿保留；改80后保存120/80。手机选择睡眠输入7.5直接保存，无名称或单位输入要求。
- QUICK-AC05通过：无任何就诊时上传TXT报告，成功进入待整理列表；点击整理提示先建立就诊；新建虚构就诊后再次整理，原件预选保留，选择就诊保存报告成功，该文件退出待整理列表。报告正文没有被自动识别。
- QUICK-AC06部分通过：浏览器权限设置为denied后实际点击录音，显示“未获得麦克风权限，可以继续用照片或文字记录”，随后文字可保存。真实麦克风采集、系统权限弹窗和设备声音质量待验证；未伪称已录制。
- 语音回放通过：使用浏览器AudioContext+MediaRecorder生成约0.12秒虚构合成音，经真实API保存为原始WEBM后刷新饮食列表；真实HTML audio播放至ended，duration有效、无解码错误。此证据仅覆盖解码/回放，不覆盖麦克风采集。
- QUICK-AC07通过：最终22项API回归通过。静态检查录音关闭抽屉时stop recorder/停止stream tracks/revokeObjectURL，以及录音中保存禁用、90秒上限、异步权限返回的generation防护。

控制台仅出现故意输入非法血压导致的预期400请求错误；没有未处理JS异常或媒体CSP错误。一次合成音频新增后仅修改hash导航没有重新载入state，显式刷新后播放通过，属于验收脚本同步调整；一次CDP权限描述符错误改用microphone后复测拒绝流程通过，均非产品缺陷。
