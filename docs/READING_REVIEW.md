## 检查范围

1. 阅读内置工作台注册、新旧账号补齐、个人/示例数据空间及主题默认值。补齐使用 INSERT OR IGNORE，不覆盖已有自定义名称与颜色。
2. HTTP/MCP 的允许记录类型与空间解析；书籍/阅读记录只能进入 reading，书籍关联按相同 space 与 kind 查询。原件上传、修改、查询和下载沿用账号/工作台权限。
3. 写入 owner 保护及前端请求快照；阅读表单保存前核对账号/工作台/空间，提交使用原快照参数，切换时清理阅读过滤与原件状态。
4. 整数页码/总页数/分钟数、真实日期、未来阅读记录、摘录内容校验；省略字段保留，明确 null 清空数值，未知页数不转换为零。
5. 书籍有活跃阅读记录或原件时阻止删除；阅读记录/文件恢复校验父书籍及页码，不允许绕过新总页数限制；最近删除使用同一空间，父项恢复遵循现有 withParent 路径。
6. 新 UI 插值转义、书架过滤、摘录原文与想法区分、独立进度更新、公共原件书籍关联/取消关联、导航与清理接入。
7. 构建加入 reading 样式；旧 bundle 清理沿用既有保留逻辑，未引入新的外部库或远程封面依赖。

## 独立执行的检查

使用 Node 24 执行 `tests/reading-backend.test.mjs` 与 `tests/reading-ui.test.mjs`，共 **11/11 通过**。后端测试是真实 HTTP/MCP、隔离临时数据库与虚构账号，包含重启持久化、跨空间拒绝、owner 冲突、文件字节及删除恢复；UI 测试验证渲染与状态规则，不将它等同于浏览器实测。

本评审未修改产品代码；未操作生产账号或生产数据。完整回归由实现者报告，浏览器与移动视口流程由 `/root/reading_acceptance` 独立执行并另行记录。

## 已知范围限制（非缺陷）

- 阅读记录中的页码是当次记录；不会自动更新书籍当前进度，界面已明确单独更新。
- 原件支持现有 PDF/图片/TXT 能力，不新增 EPUB 排版阅读器、外部书库抓取或自动封面识别。
- 有活跃关联项的书籍须先处理关联项后删除，不级联删除全部阅读历史。
